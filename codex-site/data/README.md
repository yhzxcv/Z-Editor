# 数据文件格式

一个 `data/ch-<id>.js` 就是一章。**这些文件是网站的唯一数据来源，之后手工维护，
不再依赖 `代码图鉴.txt`。** 增删改条目直接编辑这里即可，改完刷新页面就生效，没有构建步骤。

## 一个文件长什么样

```js
Codex.add({
  id: 'zombie',                  // 唯一标识，js/chapters.js 里靠文件名引用
  title: '僵尸代码',              // 章节 chips 上显示的名字
  intro: [ '……' ],               // 可选，章节前言
  groups: [
    // 形态一：普通分组，直接挂条目
    { title: '神秘埃及',
      note: '可选，分组说明',      // 显示在分组标题右边的小字
      items: [
        { name: '木乃伊僵尸', code: 'mummy' },
        { name: '无尽埃及巨人僵尸', code: 'egypt_gargantuar_danger' },
      ] },

    // 形态二：大类，挂子分组（植物用的就是这种，两级）
    { title: '图鉴中的植物',
      note: '可选，大类说明',
      children: [
        { title: '神秘埃及', items: [ /* … */ ] },
      ] },
  ],
});
```

`items` 和 `children` **二选一**。混用的话 `children` 优先，同时挂的 `items` 会被当成一个同名分组处理。

## 条目字段

| 字段 | 必填 | 说明 |
|---|---|---|
| `name` | 是 | 中文名，列表主行，也是搜索和拼音首字母的数据源 |
| `code` | 是 | 游戏代码。**点击整行复制的就是它**，必须匹配 `[A-Za-z][A-Za-z0-9_]*` |
| `src` | 否 | 来源小字，灰色标签。原 TXT 里 `[方括号]` 或降级的父级标签会落到这里 |
| `note` | 否 | 备注小字，橙色标签。原 TXT 里 `（括号）` 的内容 |

`name` 里含中文引号（如 `“哈姆雷特”僵尸`）没问题。字段值里的单引号需要写成 `\'`。

## 分组字段

| 字段 | 说明 |
|---|---|
| `title` | 分组标题，也是分组 chips 和侧栏目录上显示的文字 |
| `note` | 可选，分组说明小字 |
| `items` / `children` | 二选一，见上 |

分组标题留空字符串也可以（会被当成无标题分组），但没必要。

## 加内容

**加条目**：找到对应分组，往 `items` 里加一行。代码里有下划线会更好搜（去下划线的写法也能命中）。

**加分组**：往 `groups` 里加一项。顺序即页面上的显示顺序。

**加章节**：新建 `data/ch-xxx.js`，然后在 `js/chapters.js` 的 `CODEX_MANIFEST` 数组里加一行路径。
数组顺序就是章节 chips 的顺序。

**从 TXT 批量导入**：`tools/migrate.py` 还在，新章节可以直接用它从 `代码图鉴.txt` 生成：

```bash
python tools/migrate.py --preview obstacle    # 先看会生成什么，不落盘
python tools/migrate.py obstacle              # 生成 data/ch-obstacle.js
python tools/migrate.py --force obstacle      # 覆盖已存在的文件
```

**已存在的文件默认不覆盖**。这些数据文件是手工维护的唯一真源，误跑一次
`python tools/migrate.py`（不给参数＝处理全部章节）会把手工改动整个冲掉，
所以加了这个闸。植物和僵尸两章尤其不能再跑迁移。

`代码图鉴.txt` 的格式很随意，解析规则只会越来越复杂，所以新内容更推荐直接编辑数据文件。

## 改完自检

```bash
node tools/check.js
```

会检查：字段完整性、代码格式、有无空分组、序号唯一性，以及一批检索用例
（中文名 / 代码片段 / 去下划线 / 拼音首字母 / 跨章节 / 多关键词）。
改动数据结构之后跑一下，比在浏览器里肉眼翻要快。

## 不要动的东西

- **`id`**：`js/chapters.js` 和浏览器本地设置都引用它。
- **条目顺序**：搜索结果的同分排序会用到原序，顺序变了结果顺序也会变。
- `code` 字段只是个字符串，改它不影响游戏本身，但用户复制的就是它，改错等于害人。
